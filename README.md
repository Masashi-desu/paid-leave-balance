# paid-leave-balance

日本の一般的な年次有給休暇ルールを前提に、基準日時点の残有給日数をブラウザ上で見積もる静的 Web アプリです。  
HTML / CSS / JavaScript だけで構成し、`main` ブランチへの push を契機に GitHub Pages へデプロイできるようにしています。

公開 URL: [https://masashi-desu.github.io/paid-leave-balance/](https://masashi-desu.github.io/paid-leave-balance/)

## アプリ概要

- 1 ページで入力から結果表示まで完結します
- 半休は `0.5 日` として扱います
- 週の所定労働日数に応じた一般的な法定付与表に対応します
- 付与履歴、消化反映、失効内訳を表形式で確認できます
- 会社独自付与は、基準日時点で有効な追加日数として別枠で加算します

## 対応している計算前提

### 法定付与日数

週 5 日以上勤務、またはそれに準ずる一般的な付与表:

| 付与回数 | タイミング | 付与日数 |
| --- | --- | --- |
| 1回目 | 入社 6 か月後 | 10 |
| 2回目 | 入社 1 年 6 か月後 | 11 |
| 3回目 | 入社 2 年 6 か月後 | 12 |
| 4回目 | 入社 3 年 6 か月後 | 14 |
| 5回目 | 入社 4 年 6 か月後 | 16 |
| 6回目 | 入社 5 年 6 か月後 | 18 |
| 7回目以降 | 入社 6 年 6 か月後以降 | 20 |

週 4 日以下勤務向けの一般的な比例付与表:

| 週所定労働日数 | 1回目 | 2回目 | 3回目 | 4回目 | 5回目 | 6回目 | 7回目以降 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 4日 | 7 | 8 | 9 | 10 | 12 | 13 | 15 |
| 3日 | 5 | 6 | 6 | 8 | 9 | 10 | 11 |
| 2日 | 3 | 4 | 4 | 5 | 6 | 6 | 7 |
| 1日 | 1 | 2 | 2 | 2 | 3 | 3 | 3 |

初期実装では、出勤率 80% 以上は満たしている前提です。

### 「今年・去年・一昨年」の考え方

このアプリでは、画面上の「今年・去年・一昨年」を、カレンダー年ではなく **有休の付与日を起点にした 1 年区切り** として扱います。

- 今年 = 直近の法定付与日から計算基準日まで
- 去年 = その 1 つ前の法定付与日から次の付与日の前日まで
- 一昨年 = さらにその 1 つ前の 1 年分

内部的には、各法定付与日から次回付与日の前日までを 1 区切りとして扱っています。UI にはその期間を自動表示するため、表示と内部ロジックがずれないようにしています。

### 失効ルール

- 法定付与分は `付与日から 2 年後` に失効する前提です
- 古い付与から先に消化します
- 半休は `0.5 日` として減算します

### 会社独自付与の扱い

会社独自付与は、履歴ベースでは管理していません。  
**基準日時点で有効な追加付与日数** として、最終残数にだけ単純加算します。

そのため、過去の消化履歴や失効履歴の再現には使いません。

## モードA / モードB の違い

### モードA: 年ごとの消化数入力モード

- 入力対象:
  - 一昨年の有休消化数
  - 去年の有休消化数
  - 今年の有休消化数
- 今年・去年・一昨年の入力をもとに、古い付与から順に消化を割り当てます
- 一昨年より前の詳細履歴は入力しません
- 一昨年の消化を成立させるために必要な場合だけ、さらに前の繰越を最小限推定します
- それでも不足する場合は、警告付きの控えめな見積りとして扱います

このモードは「直近の各年ごとの消化数はだいたい把握している」ケース向けです。

### モードB: 繰越日数入力モード

- 入力対象:
  - 去年からの繰越日数
  - 今年の有休消化数
- 一昨年と去年の消化入力欄は UI 上で無効化されます
- 去年からの繰越を現在も有効な日数としてそのまま使い、今年の消化を差し引きます
- 過去の詳細消化や失効は再現しません

このモードは「細かい取得履歴は覚えていないが、会社の残数管理表で去年からの繰越日数だけ分かる」ケース向けの **簡易計算** です。

## 結果画面で表示する内容

- 総法定付与日数
- 会社独自付与日数
- 今年のはじめに持ち越していた日数
- 総消化日数
- 失効済み日数
- 現在の残有給日数
- 次回付与予定日
- 算出根拠の概要
- 付与履歴一覧
- 消化反映一覧
- 失効内訳一覧

## 注意事項と制約

- 厳密な就業規則差異や会社独自ロジックをすべて吸収する勤怠システムではありません
- 比例付与は週所定労働日数ベースの簡略判定です
- モードAは今年・去年・一昨年の 3 区分を中心に再現しており、それ以前の履歴までは完全再現しません
- モードBは簡易計算のため、過去の失効日数は再現しません
- 会社独自付与は履歴としては追跡せず、基準日時点の有効残だけを扱います
- 計算上の残数と実際の社内管理表に差がある場合は、社内ルールを優先してください

```bash
cd /Users/workSpace/paid-leave-balance
```

## GitHub Pages デプロイ方法

このリポジトリには `.github/workflows/deploy-pages.yml` を追加してあります。  
`main` ブランチへ push すると、以下の流れで静的ファイルを Pages へデプロイします。

現在の公開先: [https://masashi-desu.github.io/paid-leave-balance/](https://masashi-desu.github.io/paid-leave-balance/)

1. `actions/checkout` でリポジトリを取得
2. `actions/configure-pages` で Pages 用設定を初期化
3. `index.html` / `assets/` / `.nojekyll` を `_site/` に集約
4. `actions/upload-pages-artifact` で Pages artifact を作成
5. `actions/deploy-pages` で GitHub Pages に公開

### GitHub 側で必要な前提設定

初回だけ、リポジトリの GitHub 画面で以下を確認してください。

1. `Settings > Pages` を開く
2. `Build and deployment` の `Source` を `GitHub Actions` にする
3. `main` ブランチへ push する
4. `Actions` タブで `Deploy GitHub Pages` workflow が成功していることを確認する
5. `Environments > github-pages` または `Pages` の公開 URL から配信を確認する

## main push 後の確認方法

1. `main` に push する
2. GitHub Actions の `Deploy GitHub Pages` 実行が成功する
3. 公開 URL [https://masashi-desu.github.io/paid-leave-balance/](https://masashi-desu.github.io/paid-leave-balance/) でアプリが表示される
4. サンプル値を入力して、残数・付与履歴・消化反映・失効内訳が見えることを確認する
